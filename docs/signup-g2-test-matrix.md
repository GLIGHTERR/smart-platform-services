# G2 signup contract test matrix

| AC / branch                                                    | Test evidence                                                                                                                                                                                                    |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Required display name is trim/collapse normalized              | DTO accepts a one-word name, collapses whitespace, and rejects missing, null, blank, and over-160 values. Service persists only the normalized value.                                                            |
| Phone is optional, nullable, non-unique contact data           | DTO accepts omitted, null, and blank phone as null; validates E.164 only when a value remains. Completion tests create two accounts with the same phone.                                                         |
| Account/profile is created only at complete and never signs in | Request/verify leave users empty; successful complete atomically consumes the verified challenge and returns only `created`/`sign_in`.                                                                           |
| Same email change request reuses the active attempt            | Repeated normalized email request returns the existing attempt and cooldown, with no new outbox event.                                                                                                           |
| Changed email supersedes old work atomically                   | Request with a live `previousAttemptId` consumes the old challenge, marks its unclaimed registration outbox event superseded, and creates the replacement challenge/event in one transaction. The old OTP fails. |
| Stale and concurrent change attempts are safe                  | A stale `previousAttemptId` cannot supersede a newer attempt; only the transaction that locks the live predecessor creates a replacement.                                                                        |
| Resend, limits, single use, and rollback                       | Existing 60-second/5-per-hour, resend replacement, concurrent completion, expired/wrong OTP, and repository transaction-failure tests remain green.                                                              |
| Outbox security and consumer invariant                         | Outbox payload has no plaintext OTP; worker selects only unclaimed, non-superseded registration/recovery jobs.                                                                                                   |
